# RPO: two boxes, two round trips

## Current task (2026-11-16)

One policy controls all 23 joints through both deliveries. Both open, empty boxes start on the left table. The robot starts about 1 m from the left-table standing area, moves the small box to the right table, returns empty handed to the left, moves the large box to the right, then returns empty handed again. Success requires both boxes to remain supported on the right table and the final return to be completed.

The dimensions below are provisional scene design values, accepted for simulation; they are not measured hardware or box specifications.

| Object | Size (m) | Mass (kg) |
|---|---|---|
| Small empty box | 0.24 x 0.30 x 0.20 | 0.50 |
| Large empty box | 0.30 x 0.36 x 0.24 | 0.70 |
| Each table | 0.70 x 1.00 x 0.72 | kinematic |

The table centers are 1.30 m apart. Boxes occupy separate slots with clearance, on both tables. Change the measured values in `LearningRLlab/LearningRLlab/tasks/locomanipulation/rpo/layout.py` before physical trials. The open boxes use five physical collision panels each; there is no magnetic attachment, fixed grasp, teleportation, or scripted joint animation.

## Rewards and penalties

Each box has approach/contact/lift/carry/place/release milestones worth +5/+5/+10/+10/+10/+50 once. Each verified empty-handed return gives +10, and final completion gives +50 extra. Signed change in the current phase potential is weighted by 8; retracing progress cancels its reward. Failure gives -25; inherited energy, action changes, foot sliding, posture, joint-limit and undesired-contact costs remain.

There is no per-second hurry penalty and no time-out termination. `episode_seconds=120` remains only for framework bookkeeping; the time-out term is explicitly disabled. Positive recurring walking/alive rewards are disabled so the robot cannot earn indefinitely by waiting. PPO's finite iteration count is a compute budget, not a task deadline.

Filtered forearm contacts must touch the selected box; contact with the other box does not count. Placement requires all box corners inside the table, an upright box, low linear/angular speed, and upward table support. Release requires separation and near-zero forearm forces continuously for 1 second. Returning requires the robot within 10 cm of the left home area, low base speed, and no forearm contact with either box continuously for 0.5 seconds. A delivered box losing valid support for over 0.4 seconds invalidates the trial. Either box falling or tipping also fails.

## Important simulation/hardware distinction

The policy currently sees simulator object poses/velocities and simulated contact forces. These are not extra physical sensors and are not available just because the factory robot has motor feedback and an IMU. This version is a simulation learning experiment, not a deployable hardware policy. Before supervised hardware use, object-state inputs and phase transitions need available estimates or an explicitly constrained alternative, and the hardware interface/gains/limits require review.

No trained policy or stable transfer is established merely by the CPU tests, inverse-kinematics check, or static image. Checkpoints from the old one-box observation layout cannot be resumed directly into the new two-box policy.

```powershell
.venv/Scripts/python.exe -m pytest -q -m static LearningRLlab/tests
.venv/Scripts/python.exe tools/check_box_reach.py
```

The reach check tests both sizes and both forearms at grasp and lift height, within 90% of URDF joint ranges. It does not prove balance, collision-free motion, or grasp stability. The preview is a single static render, not a trained rollout. Avoid `--live` on the student's laptop unless an interactive viewer is wanted.

## Training

The course framework is pinned to Isaac Lab `v3.0.0-beta2.patch1`; install `robot_description` before `LearningRLlab`. `tools/train_box_transfer.sh smoke|train|video` expects the course training environment. Colab additionally needs Python 3.12, the Kit URDF importer, renderer/visualizer adapters, and explicit first-use EULA consent. An installed package is not evidence of a successful GPU rollout. Colab compatibility and training results are recorded in the shared notebook:

https://colab.research.google.com/drive/1osk2z6hihqRXN9z704KXBQozLHcvbynq

For kit-less training, set `LEARNINGRL_RPO_USD` to the absolute path of the RPO USD generated by the course converter with `principal_axes_fixed` metadata. Keep its payload files together. The optional USD spawn copies the original robot's physical property overrides and preserves the converted file's authored physics variant; the actuator configuration is unchanged. The training shell then selects `--viz none`. Model conversion still requires Kit once. This does not produce rendered videos by itself.

The current Colab setup uses Isaac Sim 6.0.1.0, Python 3.12 and the pinned Isaac Lab checkout. Its dependency resolver required documented overrides for `coverage==7.4.4` and `packaging==26.0`, and selected Isaac Sim's PyTorch 2.11. Runtime rollout validation remains necessary; package installation alone is insufficient.
